## Recommended scope for the next reviewed candidate

1. **One behavioral core, many adapters.** Refactor to a concise, single canonical decision reflex (target approximately 6–8 KB) emphasizing response-mode choice, honesty, facts vs assumptions, ownership, independent challenge, practical next steps, ethical/safety boundaries and user thresholds. Derive platform adapters rather than maintaining multiple divergent behavioral rules. Preserve core intent and R1–R7; do not trade away safety to fit a target. Refactoring must pass behavioral parity tests.
2. **On-demand source files, no database ever.** Canonical ledger: `sources/book-source-ledger.md`; professional references: `sources/reflex-references.md`; dated studies: `sources/studies/`. Keep provenance and edition-specific coverage. Use zero to two relevant sources in ordinary advice, never the entire bibliography. If a platform cannot access GitHub, state the access limitation and use the core without faking retrieval.
3. **No reflex inflation.** S08 chess: domain-only. S09 Atomic Habits: enhances existing R2 (systems/friction). S10 wine atlas: domain-only. S11 The Three-Body Problem: fictional illustration supporting the *existing* evidence-challenge method; ask what observable evidence would overturn a premise when useful. No R8; no new claims of reading entire books.
4. **Platform exports.** Rebuild ChatGPT Project, Gemini Gem, Claude offline ZIP, portable instructions, and Microsoft 365 Copilot Agent Builder text from reviewed canonical content. Microsoft Agent Builder has a documented 8,000-character limit: target ~6,000–6,500 with headroom; verify the final UTF-16 character count. Keep GitHub Copilot's repo skill short and conditional, and ensure its source/footnote version matches v0.7.4. Copilot-host-specific live behavior remains unverified unless actually tested.
5. **Release engineering.** Advance `release.json` and all footer/version labels to v0.7.4; rebuild all generated downloads and SHA256SUMS, test/review ZIP parity, privacy guard, source provenance and links; run Python and Node checks. Obtain explicit human approval on the reviewed candidate **before** merge to `main`, tagging or publishing a GitHub Release. Existing installed copies never auto-update.

## Human validation: acceptance cases

- Clear direct question → direct answer, no generic counseling or forced book discussion.
- "Please listen; no advice" → attentive listening without a recommendation or footer.
- "The €400 deal is within my €450 budget but not worth it" → respect refusal; a ceiling is not a purchase target.
- Manager asks for routine approvals → inspect incentives/decision rights, recommend one reversible delegation experiment.
- Consequential unverified assumption → state what evidence could reverse the recommendation; independent verification rather than fabricated agreement.
- Relevant S11 question → cite only verified authorized excerpt, with partial-coverage warning; do not treat fiction as empirical evidence.
- GitHub Copilot routine code edit → no advice persona; explicit LuminousPeace decision request → conditional skill available.
- Microsoft 365 Copilot → instruction text within 8,000-character bound and equivalent core behavior.
- Release integrity → reproducible package assets, no changes to previously published Ask Him archive, no personal data in public files.
